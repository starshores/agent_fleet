沿原计划，本批补齐 V3 成员生命周期和事件接单，业务包契约仍为 schema 1 / platform_api 1。角色工作区、权限上限、模型和原生历史仍由部署层显式绑定；没有按具体业务或角色名修改基座。

1. **持续接单入口。** 新增前台 `serve`，按显式 Actor、运行时配置和工具串行处理该角色的 queued 任务；支持任务数和运行时长上限。一个成员持续运行，每次 Attempt 仍拥有独立原生进程/thread，不等于原生会话恢复或系统服务托管。
2. **成员与执行双重租约。** 同安装/角色只允许一个活动成员；选任务、创建 Attempt、绑定成员和标记 busy 在同一事务中完成，其他领取入口不能绕过成员排他。停止、过期、旧身份或代次失效会阻止续租、纠偏回执和迟到结果发布；未知执行保留 needs_reconcile，不自动重跑。
3. **事件驱动接收。** Windows 原生目录通知先建立监听再读队列，实际覆盖跨进程提交和等待期间的新任务。工作中可继续持久化纠偏、回答 Decision、回填子任务和请求停止。明确属于父请求的已完成子结果可进入恢复执行的提示词，outbox 不自动确认。非 Windows 常驻等待当前明确报不支持。
4. **如实报告状态。** `members` 只读，`online` 仅表示租约与绑定有效；`owned_attempt_active` 仅表示有效执行归属。停止请求先隔离发布权限，再由拥有者确认执行进程终止；不能从 stopping、登记或心跳推断模型连通或子进程退出。
5. **schema 4显式迁移。** schema 1/2/3先备份再升级，保留历史并撤销旧 Actor；新成员表初始为空。schema 2/3存在 running Task/Attempt 时拒绝迁移。没有对真实状态执行升级，也未启动、重启或切换现有服务。

兼容线复核另修复两处问题：会话恢复在实际写 presence 的同一锁内核对原会话，防止覆盖刚发生的新绑定；信使证据缺失或损坏时不再仅凭 wait 报告 armed。同步调整受既有导入变化影响的测试替身。只运行这三组合成兼容测试，共40项全部通过，不将其表述为旧兼容线全量验收。

## 历史交付：逐角色部署与运行中纠偏（2026-10-12）

用户同意进入下一阶段。沿原计划把业务可替换要求推进到部署和执行边界：业务包保留角色、知识、流程及通用能力；本机目录、访问上限和Codex配置由部署层绑定。基座没有增加具体业务或角色名分支。

1. **逐角色工作区。** 安装时可为每个角色指定工作目录及 `none/read-only/read-write` 访问上限；未指定沿用安装默认目录、权限为none。同一安装可精确共享目录，不同安装根不可重叠；部署绑定不可原地修改。权限上限仅供后续工具授权使用，本批仍为纯文本执行，不开放业务文件工具。
2. **App Server运行时。** `codex-app-server` 与 `codex-exec` 共用 Task/Attempt/Lease 生命周期。每次Attempt拥有自己的stdio进程树，创建新原生thread/turn；只接受本次RPC返回的精确ID。成功需完整终态、最终文本和进程树退出证据，受控关闭保留实际退出码。
3. **执行中补充信息。** `steer-attempt` 持久保存正文和请求ID，再按序发送；状态为pending→sending→accepted，无法确认时转held。不能跳过未决输入、不能自动重放；完成事务检查未决输入，避免结束瞬间的新信息被静默丢弃。`runtime-inputs` 提供只读查询。投递回执只表示原生运行时接收，不表示模型采纳，更不等于审批。
4. **隔离约束。** 原生历史绑定安装、角色及代次，运行目录与所有业务工作区隔离。App Server不具备exec的忽略用户配置开关，因此专用目录含自定义配置、hooks或技能时明确拒绝。原生工具和审批请求只返回拒绝，不把运行时请求转换成平台批准。
5. **schema 3显式迁移。** schema 1/2先完整备份再事务升级，保留历史、撤销旧令牌；逐角色目录初始继承旧安装目录且权限none。schema 2存在运行中任务/Attempt时先拒绝迁移。失败回滚，读取不会自动升级；未操作真实状态或旧bus数据。

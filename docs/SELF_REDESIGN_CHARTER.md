# 全功能自我迭代宪章(Self-Redesign Charter)

> **用户授权 2026-09-16(原话)**:"全功能的自我迭代,你可以将所有功能都进行重设计,this is everyone module,为了更好而重构造,但是业务和基建分离,永远在线是铁率(律)"。
> 即:**所有模块**都可为更好而重设计/重构造;两条铁律不可违。

## 两条铁律(每个重设计提案的硬闸)

### 铁律1:业务 / 基建分离(separation)
- 承接 `bus-pluggable-business-platform`:bus=通用 agent 管理平台,业务=可插拔负载。
- **三问验收**每案必过:①归属问(这是机制还是业务内容?)②清除问(业务清完平台能空载跑?)③换域问(换业务域要改平台代码?)。
- 重设计**不得**把业务口径/数据焊进平台代码;业务内容一律业务侧存储 + `path_registry.json` biz-data 登记。

### 铁律2:永远在线(always-online)
- **任何重构不允许下线/失联**:协作频道(事件自醒·轻问·可打断)在重构全程保持可用。
- 落地方式=**增量绞杀(strangler)、禁大爆炸切换**:旧机制活着直到新机制**实证接管**(validate-then-trust·辩证三段正/反/合);双跑期新旧并存,切换=灰度非一刀切。
- **反例镜鉴**:2026-08-27 daemon 化=一次性全舰切换→协作频道退化→全面回退。重设计再激进,在线性不许赌。
- 迁移类动作沿用铁序:**先广播 → 动刀 → 再确认**(消费方知情·瞬时窗口有预告)。

## 流程(每模块一案)
1. **Inventory**:以 `bus_mechanisms.json`(96 机制/13 类注册表)+ UI/hook/记忆/探针面为全集,各 owner 盘自己 lane 的重设计候选(痛点/debt/更优形态)。
2. **提案(proposal)**:痛点→新形态→迁移路径(如何保在线)→验收判据。
3. **三闸 gate**(过不了不动工):①核心价值闸(强化还是削弱"便宜协作+可打断"?)②分离闸(铁律1三问)③在线闸(铁律2·双跑/灰度方案齐备?)。
4. **增量执行**:小步提交·每步 smoke(bus_smoke/ui_smoke 金标准)·可回滚。
5. **实证验收**:Master数分对抗验证(非自证);行为对比(探针可作回归仪)。
6. **发版记录**:机制改动照常 genesis + tag(MasterAgent 自动发版·大版本目标用户定)。

## 与迭代波的关系
迭代波 v1(仪器驱动:探针/记忆/缺席)是本宪章的**运行态采样层**——探针 verdict / 记忆 trap 实证 / 阈值实测持续喂重设计候选。宪章把「发现→重设计→验证→发版」闭成常态循环:**fleet 自己迭代自己,用户只拍大方向**。

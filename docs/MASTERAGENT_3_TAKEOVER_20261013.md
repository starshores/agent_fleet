## 接管边界

3.0 基座可运行纯文本角色，但**尚不能直接替代现有 MasterAgent 或全体业务角色**：当前模型没有业务文件工具或人工审批桥，不能自主调用协调命令；旧 bus 信使不向 3.0 提交任务，3.0 outbox 也不会自动送回旧 bus 或 WebUI。原生 resume、Windows 服务托管及生产迁移未交付。让同一业务任务同时进旧 inbox 与 3.0 队列会造成双领风险；停掉旧信使后直接启动 `serve` 则会失去现有消息通道。

旧入口不止 `ab send`：请求、通知、工作组、用户待办及 WebUI 都可能写角色 inbox。只在 `ab send` 增加 3.0 分流会漏掉其它来源。切换必须在统一领取所有权处挡住旧消费者，或令所有写入来源共用一个经核对的路由；适配器需要持久记录旧消息 ID↔3.0 request/task/attempt ID、投递阶段与完成回执，以便断线时核对而非复制回 inbox 重放。对 `notice`、`fyi.no_receipt`、审批门禁和业务消息归口仍须保留各自语义。

| 接管层 | 必须落实的单一事实来源 | 放行观察 |
| --- | --- | --- |
| 发行维护 | 3.0 包哈希、源码、版本与发布记录一致 | 本机发行说明、增量资料、跨 bus 交接已更新；不凭文件名判断上线 |
| 新任务入口 | 每条任务只选旧 bus 或 3.0 一个入口，保留请求 ID 与来源映射 | 无双重领取；失败和未知状态留原处待核对，不自动重放 |
| 消息出口 | 3.0 结果、notice 与旧 bus/WebUI 的真实送达回执分开 | `outbox pending` 不宣称用户或 agent 已收到 |
| 角色运行 | 精确身份、角色包、记忆、工作区、模型、专用 home 与能力上限逐项绑定 | 模型能完成该角色的真实职责，不以 `members.online` 代替连通性 |
| 停止和回退 | 先停新接纳，再确认拥有者进程退出、核对在飞 Attempt | 未知工作保留；回退只改后续任务路由，不覆盖新状态或清旧历史 |

# MasterAgent 3.1 UI / 工作台审阅建议

日期：2026-10-19  
审阅范围：MasterUI，面向真实用户路径、状态语义、旧 UI 缺口及操作风险。  
方式：只读审阅当前 3.1 文档与相关实现；未修改其他文件、未重跑测试、未连接旧控制台。最多 5 项优先建议。

## 1. P1：补清“保存任务后由谁执行”的交接路径

**建议：** 用户保存新任务后，在回执旁呈现当前业务/代次的可接单成员、领取状态，以及没有可用执行者时的下一步。将“公共操作已启用”明确限定为可以写入平台命令；不要让它看起来像执行服务或模型已经就绪。

**已实现事实：** 任务表单说明任务只保存到 V3 队列，不自动启动执行服务（masteragent/workbench_assets/views.mjs:86-90）；成功回执说明等待独立执行服务领取（masteragent/workbench_assets/commands.mjs:40-44）。操作门禁检查公共命令配置、当前业务和代次（commands.mjs:6-15），顶栏“公共操作已启用”取自命令开关（masteragent/workbench_assets/app.mjs:81）。团队页可显示成员租约与当前执行归属，但模型连通性仍是未验证（views.mjs:299-320）。

**待验证项：** 无成员、租约过期、成员可接单但模型连通未验证时，用户是否知道任务是否有人会领取、下一步该做什么；需与真实独立执行器路径一起验收。本次仅静态核查。

## 2. P1：提供明确的跨代次任务链入口

**建议：** 在发现同一任务存在其他代次记录时，提供可点开的关联代次/执行链视图，逐项标注代次、执行尝试、结果及当前执行归属；保留“当前记录过滤”与“历史时点快照”的区别。

**已实现事实：** 详情会提示当前只显示所选代次相关记录，并在存在跨代记录时提示当前详情不含完整执行链（masteragent/workbench_assets/views.mjs:263-265）。查询按所选 dispatch_generation 读取任务，并按所选代次读取 attempts、events、inputs、decisions、results，只返回一个 history_available 布尔值（masteragent/workbench_query.py:332-373）。工作台说明明确过去代次查询不是历史时点快照，完整跨代次执行链尚待实现（docs/MASTERAGENT_3_1_WORKBENCH.md:128）。

**待验证项：** 续接后多代尝试、决定与结果之间的关联是否完整可达，及截断时是否仍可正确辨认链路；本次未运行数据场景。

## 3. P1：在工作台概览中把待答事项称为“平台决定”

**建议：** 将概览中的泛称“待确认事项”改为“平台决定待答复”，并在后续实现原生工具审批时单列入口、状态与通知。继续保持平台决定、运行中补充信息和原生审批三种语义相互独立。

**已实现事实：** 概览目前用“待确认事项”计数并引导用户进入任务（masteragent/workbench_assets/views.mjs:104-123）。决定页已说明这是平台公共决定、不是原生工具审批，并要求明确选择批准或拒绝（views.mjs:223-237；masteragent/workbench_assets/commands.mjs:29-32）。原生审批仍是未实现契约（docs/MASTERAGENT_3_1_NATIVE_APPROVAL_CONTRACT.md:1-15）。

**待验证项：** 当前没有 RuntimeApproval 实现；未来当同一 attempt 同时有平台决定与原生审批时，需验证导航、通知与答复不会串用。

## 4. P2：在进展处突出快照时效，不让“实时”形成即时性的预期

**建议：** 在任务时间线与目录中的“实时”项旁显示最后快照时间或“公开事件快照”说明；后续再接持久事件游标与断线补读，不以轮询或单次刷新冒充实时订阅。

**已实现事实：** 顶栏以 observed_at 显示快照时间，刷新失败时保留旧数据并提示；页面在网络恢复、重新可见时刷新（masteragent/workbench_assets/app.mjs:42-79,164-174,257-264）。工作台说明指出目前没有持久事件游标或实时推送，不能保证后台即时更新（docs/MASTERAGENT_3_1_WORKBENCH.md:132）。原功能目录也把旧“实时”标为公开事件快照、未迁入原生日志流和持久订阅（masteragent/workbench_assets/navigation.mjs:22-24）。

**待验证项：** 长时间打开页面、连续刷新失败、事件超过有界列表上限时，用户能否识别数据时效和不完整状态；本次未进行浏览器验收。

## 5. P2：按真实缺口确定旧控制台功能迁移优先级，并保留兼容回退

**建议：** 在旧入口继续保留期间，按日常值守、数据诊断、任务组织等用户场景排定原生迁移次序，并逐项记录入口、操作语义、来源、权限、错误状态和验证范围。优先评估 wait/selfwake、上下文、历史用量、提示词来源、任务线和工作组等仍有明显差异的能力；未完成等价承接前不撤旧入口。

**已实现事实：** 21 项目录给出局部/未承接状态和可配置的本机深链（masteragent/workbench_assets/navigation.mjs:5-43）。迁移清单明确深链不证明旧服务在线，也不代表功能已迁入（docs/MASTERAGENT_3_1_UI_COVERAGE.md:5-14）；wait/selfwake、上下文、历史用量、提示词来源、任务线与工作组等缺口列于 UI_COVERAGE.md:22-33。链接仅根据显式本机地址生成；当前没有探测旧服务（navigation.mjs:29-43）。

**待验证项：** 旧服务加载新版页面后，各页签深链是否确实到达对应页面；旧服务离线或仍加载旧版页面时，用户能否识别并恢复访问。当前证据为链接构造和目录测试，不是旧服务在线验证；文档也记录旧服务未在本批重启或点击验证。

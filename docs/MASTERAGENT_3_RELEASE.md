# MasterAgent 3.0.0 正式版

发布日期：2026-10-13。发布范围为 Windows 前台常驻调度与纯文本协作基座，状态 schema 4，业务包 schema 1 / platform_api 1。此为本机正式发行；不等于已迁移或接管现有旧 bus fleet。

## 已放行能力

业务包、部署配置与平台核心分离；同一构建支持空载与 A→B→A 切换。角色通过明确的 Actor、安装和代次绑定持续接单，独立 Attempt 拥有原生 App Server 进程/thread/turn。平台提供成员排他、双租约、事件唤醒、结果与通知持久化、文本纠偏、停止和显式任务恢复。

本次最终真实验收使用独立状态、虚构文本和显式部署。两个角色各连续完成两项任务，验证真实 turn/steer 回执及最终文本采纳；在飞停止和本次拥有的原生进程断线后保留 needs_reconcile，确认退出后显式 reconcile 才重试；随后完成 B 和恢复 A 的真实执行。最终构建通过10个原生 Attempt；此前首轮执行2个原生 Attempt后失败，两轮实际合计12个。此为平台Attempt计数，不将其表述为包含原生内部重试在内的精确计费请求数。

固定验收原生版本为 `codex-cli 0.162.0-alpha.17.2`，请求模型为 `gpt-6-astra`，原生 thread/start 报告的模型逐次核对。旧固定可执行路径已经失效，部署必须使用实际存在的明确路径及固定版本；不承诺任意 Codex 版本兼容。

新版新增的 partial_answer 仅作为中间输出，不能替代或覆盖最终答案。适配器仍要求精确终态、最终文本与实际进程树退出证据。

首轮暴露原生自动生成bundled skills目录，导致第二任务preflight拒绝。修复在显式原生启动参数中关闭 `skills.bundled.enabled` 和 `skills.include_instructions`；继续拒绝home中的自定义skills目录或配置。首轮失败报告、完整事件和原候选包保持原样，第二轮使用独立目录与重建候选包，不覆盖失败历史。

## 使用与并存

需要Python 3.11或更新版本。独立包入口为 `python -B masteragent-3.0.0.pyz`；源码入口为 `python -B -m masteragent`。状态根必须明确指定，默认观察不创建状态。

启动顺序为：验证业务包→install→activate→register→选择匹配的运行时JSON→runtime-prepare→原生认证→runtime-check→serve。逐角色 `--actor-file`、`--runtime-config` 和 `--tool` 均明确选择；多角色分别启动成员。完整参数与停止说明见 [成员手册](MASTERAGENT_3_MEMBERS.md)。

验收脚本为 `scripts/acceptance_v3.py`。先使用 `--prepare` 生成独立目录和待审阅文本，再显式 `--run --allow-real-model-calls`；`--verify` 只接受实际执行证据。失败保留状态与证据，不自动重跑未知执行。

旧 fleet 与 V3 不共用任务队列、领取标记或Actor。灰度承接时，每条业务任务只能选择一个入口；不能向两条运行线重复派发。此次没有导入真实业务任务、接管旧会话或重启旧服务。

原生认证与角色历史当前仍随专用home部署，现有桌面登录不会自动出现在新home。本次用户逐项完成部分原生授权后，明确授权仅在本次验收目录之间复用新生成的认证；首轮剩余两个home及第二轮重建的五个used home通过不解析、不显示内容的本机复制完成。该授权不延伸到私人/旧fleet认证或后续部署；平台未增加隐式复制认证功能。这项重复登录体验仍是后续部署优化项。

## 升级、恢复与边界

schema 1/2/3仅通过显式migrate备份升级到4，旧Actor撤销；schema 2/3存在running Task/Attempt时拒绝升级。dev.4不能打开schema 4。新状态已产生工作后，不可直接用旧备份覆盖。

先停止接纳，再由拥有者确认进程退出；未知执行保留待核对。确认重复执行无副作用后才显式reconcile。回退保留新状态、备份与原生历史，不清理未知任务或未确认通知。

online只表示租约与身份有效；owned_attempt_active只表示执行归属；accepted只证明传输接收。outbox持久保存不等于已自动投递或已读。任务接续不等于native resume。

本版不提供原生会话恢复、模型自主调用平台命令、运行中人工审批桥、业务文件工具、系统服务托管或生产迁移。纯文本基座的正式发布不替代这些能力的独立验收。

接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)，并以本机固定原生版本生成的schema核对实际字段。

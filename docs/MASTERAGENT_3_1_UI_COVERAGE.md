# MasterAgent 3.1 界面功能迁移清单

更新：2026-10-19。当前开发代码为 `3.1.0-dev.3`，schema 5，公共 API 保留 `3.1-dev1`。下表保留 dev.1 对 `ui/` 界面文件和 HTTP 路由的逐项核对基线；dev.2 公共操作、运行事实、审阅后阶段 A 和阶段 B 的变化分别记录。

**3.1 dev.2 已增加原功能目录、显式兼容链接、四项公共操作及运行事实展示，仍未完整承接现有 UI。五个主入口是信息分类，不代表原有 21 个页签的功能已经归并完成。现阶段不能用新工作台替换现有控制台。**

本清单依据源码核对功能存在性；没有启动旧服务、访问生产业务、读取原生私人会话或执行旧 UI 写操作。2026-10-12 的旧界面浏览器巡检另见 [巡检记录](CODEX_UI_AUDIT_20261012.md)，不作为本次在线复测结果。

## 状态含义

- **局部对应**：新工作台有相关能力，但字段、操作或数据来源不等价，尚未完成迁移。
- **未承接**：新工作台中没有对应可用功能。
- **完整承接**：需同时覆盖用户工作流、来源与权限、交互和验证；本次未将任何旧页整体判为完整承接。
- 下表“去向与批次”是迁移安排，不是已实现状态。当前 UI 的“已提供兼容链接”仅表示已配置可点击链接，不证明旧服务在线，不能计为功能已重建；真正的兼容可达还需单独在线验证。

## dev.1 核查时发现的缺口

以下保留 dev.1 核查结论及当时源码位置，便于追溯用户指出的问题；当前已补接部分以上面的 dev.2 差异表为准。完整迁移尚须逐项验证，不能因新增目录或按钮而自动消除其余缺口。

1. **兼容入口没有实际接通。** `views.mjs:275–276` 只有“未配置兼容入口”文字；不能计为“旧功能仍可从新 UI 访问”。需要显式配置本机控制台来源、可点击导航与连接失败提示，且查看新 UI 不应隐式访问旧接口或启动旧服务。
2. **连接卡不是实际连接观测。** `workbench_query.py:289–297` 将登录/连通标为未验证、模型/用量标为 null；这不是已经读取当前 Codex/Claude 的运行信息。新卡片不会自动显示旧舰队的在线 agent。
3. **新 UI 尚无公共写操作。** `workbench.py:187–198` 拒绝 POST/PUT/PATCH/DELETE；旧 `routes.py:190–257` 中的任务派发、TODO 操作、答复、手动 done、模型偏好、自愈、长程批量决定、ASR 启停、打开文件/路径均未迁移。
4. **部分旧操作需要保留用户目的、重设实现语义。** 手动 done 不能绕过 V3 执行归属；清理回报不能变成删除事务审计；旧 supervise 不能变成页面启动副作用；独立待办、任务线、工作组和长程图不能被单 Task/Decision 名称替代。
5. **跨页交互也有差距。** 旧页的用户缺席提醒/确认答复、全局健康与上下文徽标、事件推送、通知和未提交编辑保护，不能只核对菜单名称。新页已有只读刷新、选中/滚动保持、断线旧快照和业务隔离；表单草稿保持、持久事件补读和通知仍待后续实现。
6. **历史尚非完整执行链（dev.1 基线）。** 当时详情限定所选代次、数组有界截断并提示其他代次记录。阶段 A 已补独立跨代只读查询和分页；原筛选详情的语义保留，不能把任务链描述成历史时点快照。
7. **旧长程批决策有需要重新审视的默认行为。** `page_js_panels_b.py:306` 将未选择项按 reject 提交。迁移时应显式区分未选择与拒绝，不能为追求表面功能等价而无提示照搬这一默认值。
